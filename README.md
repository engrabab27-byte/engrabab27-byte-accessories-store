# FEDAA STORE

متجر ثابت يعمل على GitHub Pages، وتستخدم لوحة الإدارة Supabase Auth وقاعدة بيانات PostgreSQL وSupabase Storage للمنتجات والطلبات والصور.

## إعداد Supabase

1. أنشئي مشروعاً مجانياً من [supabase.com](https://supabase.com/) واحفظي كلمة مرور قاعدة البيانات في مكان آمن.
2. من **Project Settings → API** انسخي **Project URL** و**anon/public key**. لا تنسخي `service_role` أو `secret key` إلى ملفات الموقع.
3. افتحي `supabase-config.js` واملئي `url` و`anonKey` بالمعلومات السابقة. سيظهر معرّف المالك في خطوة لاحقة.
4. من **Authentication → Users** اختاري **Add user** وأنشئي مستخدم المالك ببريد وكلمة مرور قوية. أوقفي تسجيل المستخدمين العام من **Authentication → Settings/Signups**.
5. معرّف حساب الأدمن الحالي `3e8f1da7-10f7-4d57-9d20-cb81446e9982` مضاف إلى `supabase-config.js` وسياسات `supabase-setup.sql`. إذا تغير حساب المالك لاحقاً، استبدلي UUID في الملفين ثم أعيدي تشغيل SQL لتحديث السياسات.
6. افتحي **SQL Editor → New query**، الصقي محتوى `supabase-setup.sql` وشغّلي الاستعلام. سينشئ الجداول والسياسات ويضبط حاويتي `products` العامة و`order-receipts` الخاصة. لتصفير المنتجات التجريبية القديمة فقط شغّلي أيضاً `supabase-clear-demo-products.sql` مرة واحدة.
7. استخدمي أمر النشر الموحّد الموضح أدناه لإرسال التعديلات إلى GitHub Pages. بعد تسجيل الدخول إلى `admin.html`، أضيفي المنتجات الفعلية من لوحة الإدارة.

## رابط الموقع الدائم

الرابط الدائم المعتمد للمتجر هو https://engrabab27-byte.github.io/engrabab27-byte-accessories-store/، من المستودع `engrabab27-byte/engrabab27-byte-accessories-store`. يظل الرابط نفسه مع كل نشر للكود أو تحديث للصور ما دام النشر على المستودع نفسه؛ لا تنشئي موقعاً أو مستودعاً جديداً لكل تحديث، ولا تغيّري اسم المستودع أو حساب GitHub المرتبط بالنشر. يظهر الرابط المعتمد أيضاً في **Repository → Settings → Pages**. إذا كان المطلوب نطاقاً خاصاً بدلاً منه، فيلزم امتلاك النطاق وضبط DNS وإضافة ملف `CNAME` بقيمته.

## نشر التحديثات

تم ربط مجلد الموقع بفرع `main` في المستودع الدائم. بعد حفظ التعديلات ومراجعتها، شغّلي من PowerShell في مجلد المشروع:

```powershell
.\deploy.ps1
```

ينشئ الأمر commit ويرفعه إلى `main` بعد التحقق من المستودع والفرع؛ ثم ينشر GitHub Pages التحديث تلقائياً على الرابط الدائم نفسه. يمكن تمرير وصف للتحديث، مثلاً `.\deploy.ps1 -Message "تحديث صور المنتجات"`. عند أول دفع قد يطلب Git تسجيل الدخول إلى GitHub عبر Git Credential Manager. لا يرفع السكربت تلقائياً عند كل حفظ، لتفادي نشر ملفات غير مكتملة؛ شغّليه بعد اكتمال التعديل.

إذا كان المشروع مضبوطاً مسبقاً وظهرت أخطاء RLS عند إرسال الطلب أو رفع صور المنتجات، شغّلي `supabase-fix-rls.sql` مرة واحدة من **SQL Editor** في مشروع Supabase نفسه. يعيد تثبيت السياسات الآمنة ويضبط صلاحيات دالة حفظ الطلب؛ لا يفتح قراءة الطلبات أو إدخالها مباشرة للزوار. تحققي أن UUID المالك في السكربت يطابق `adminUserId` في `supabase-config.js` وحساب المالك في **Authentication → Users**.

إذا ظهرت رسالة `products_category_check` عند حفظ منتج في قسم «غوايش» أو «أطقم»، شغّلي `supabase-fix-product-categories.sql` من **SQL Editor** في مشروع Supabase نفسه المحدد في `supabase-config.js`. يعيد السكربت إنشاء القيد بقائمة الأقسام المعتمدة ويعرض تعريفه بعد التحديث. تحققي من عنوان المشروع قبل التشغيل؛ حفظ الملف وحده لا يغيّر قاعدة البيانات الحية.

تتطلب لوحة الإدارة HTTPS ومشروع Supabase مضبوطاً. يمكن وضع رابط المشروع و`anon/public key` في المستودع لأنهما مفاتيح متصفح عامة ومقيدان بسياسات RLS؛ لا تضعي مطلقاً مفاتيح `service_role` أو أسرار قاعدة البيانات في JavaScript أو HTML.

## تخزين البيانات وحماية الوصول

- جدول `products`: قراءته عامة لعرض المتجر، وتعديله متاح فقط لمستخدم المالك المحدد بـ UUID في سياسات RLS.
- يبدأ المتجر بقائمة فارغة؛ لا يوجد كتالوج تجريبي تلقائي أو زر لإعادة إدراجه.
- يدعم المنتج عدة صور مرتبة في `products.images`، وتُعرض كمعرض قابل للسحب مع نقاط توضح الصورة الحالية. تشمل أقسام المتجر غوايش وأطقم إكسسوارات. خيار صورة الصفحة الرئيسية يُحفظ في `store_settings`؛ تبقى صورة Unsplash الحالية وعبارة «مصممة لتدوم» افتراضيتين ما لم تُحفظ صورة أخرى.
- يتيح إتمام الطلب دفع نصف قيمة المنتجات الآن أو دفعها كاملة؛ لا تدخل رسوم التوصيل في إجمالي المنتجات أو الدفعة الإلكترونية. تظهر رسوم التوصيل للعميل بأنها تُحدد بعد مراجعة العنوان وتُدفع نقداً عند الاستلام.
- يستخدم نموذج الطلب رقماً واحداً باسم `customer_phone`، ويقبل لقطات الشاشة وصيغ الصور الشائعة من الهواتف بما فيها HEIC/HEIF وAVIF وPNG كبيرة الحجم (حتى ٥٠ ميجابايت قبل الضغط). تُحوّل الصورة في المتصفح إلى WEBP أو PNG مضغوطة قبل رفعها إلى `order-receipts`، ويُحفظ مسارها في `orders.receipt_path`. تُحفظ بيانات الطلب مؤقتاً في `localStorage` قبل الرفع، ثم تُحذف النسخة المحلية عند نجاح الحفظ؛ لا تتضمن النسخة المحلية ملف الإيصال نفسه.
- تُرحّل قاعدة البيانات أسماء الاتصال والعنوان والمبالغ إلى `customer_phone`, `customer_address`, `total_amount`, `paid_amount`, و`remaining_amount` مع إبقاء الأعمدة القديمة للتوافق؛ وتمثل هذه المبالغ قيمة المنتجات فقط. تُخزن رسوم التوصيل منفصلة في `delivery_fee` وتحددها الإدارة من الطلب، ويعرض النظام مجموعها مع رصيد المنتجات كمبلغ التحصيل النقدي عند الاستلام. تُحسب مبالغ المنتجات داخل دالة SQL ولا تعتمد على قيم يرسلها المتصفح.
- تعرض بطاقة وسيلة الدفع المختارة كود فودافون كاش السريع ورقم المحفظة والمبلغ المستحق مع رابط فتح الاتصال، أو رابط متجر InstaPay الرسمي حسب نظام الهاتف. لاستقبال InstaPay يستخدم العميل رقم الموبايل المسجل، ثم يختار التحويل إلى رقم موبايل داخل التطبيق؛ لا يوفر الموقع رابط تحويل InstaPay يملأ بيانات المستفيد أو المبلغ تلقائياً.
- تعرض لوحة الطلبات شارة واضحة لخطة الدفع، رصيد المنتجات، رسوم التوصيل، وإجمالي النقد المطلوب تحصيله عند الاستلام. على الإدارة إدخال رسوم التوصيل في الطلب ليظهر الإجمالي بدقة.
- تقبل واجهتا المتجر ولوحة الإدارة صيغ الصور الشائعة التي يدعمها المتصفح، بما فيها HEIC/HEIF وAVIF، دون حدّ ثابت لحجم الملفات الأصلية في لوحة الإدارة. تُصغّر الصور وتُحوّل إلى WEBP (أو PNG إذا لم يدعمه المتصفح) قبل المعاينة والرفع؛ ويُحمّل قارئ HEIC من CDN عند الحاجة فقط. يتطلب تحويل HEIC اتصالاً بالإنترنت، وقد لا يمكن فك الصور التالفة أو الصيغ التي لا يدعمها المتصفح أو القارئ.
- يسجل كل طلب طريقة الشحن الافتراضية «توصيل للعنوان»، ويعرض العنوان والمنتجات والكميات وطريقة الدفع وصورة الإيصال الخاصة في لوحة الإدارة؛ يمكن تكبير المعاينة وفتح الصورة بالحجم الكامل.
- جدول `orders`: إدخال الطلبات يتم عبر دالة SQL `create_order` التي تتحقق من الحقول، وتقرأ الأسعار الحالية من قاعدة البيانات، وتحسب إجمالي المنتجات والمبلغ المدفوع والمتبقي حسب اختيار العميل. لا يستطيع الزوار قراءة الطلبات؛ المالك فقط يستطيع قراءتها وتحديث حالتها.
- حاوية `products`: صور عامة للعرض، ورفعها/إدارتها يتطلب جلسة المالك.
- حاوية `order-receipts`: خاصة، رفع الإيصال محدود بنوع الصورة وحجم ٥ ميجابايت، ولا يستطيع قراءته إلا المالك من خلال رابط مؤقت.
- إذا رفضت سياسات RLS رفع صور المنتجات، أعيدي تشغيل `supabase-setup.sql` في SQL Editor للمشروع نفسه المحدد في `supabase-config.js`، وتأكدي أن `adminUserId` يطابق UUID مستخدم المالك في **Authentication → Users**. لا تعطيلي RLS ولا تستخدمي مفتاح `service_role` في المتصفح.
- لا تستخدمي كلمة مرور ثابتة داخل كود الواجهة. تسجيل الدخول يعتمد على Supabase Auth، والتفويض الفعلي تفرضه سياسات قاعدة البيانات والتخزين.

سعر المنتجات وإجمالي الطلب يُعاد احتسابهما داخل PostgreSQL، لكن هذا النموذج لا يوفر معالجة دفع إلكتروني، ولا يمنع إساءة استخدام عامة لخدمة إرسال الطلبات أو استهلاك حصة الخطة المجانية. راقبي استخدام Supabase، وأضيفي CAPTCHA/حدود إرسال عبر وسيط خادمي إذا تعرض النموذج للإساءة. راجعي إيصال التحويل يدوياً قبل تأكيد الطلب.

## الملفات المهمة

- `index.html`, `styles.css`, `app.js`: المتجر والطلب.
- `admin.html`, `admin.css`, `admin-client.js`: لوحة الإدارة.
- `supabase-config.js`, `supabase-client.js`: إعداد اتصال المتصفح.
- `supabase-setup.sql`: الجداول والسياسات والدالة المخزنة وحاويات التخزين.
- `supabase-fix-product-categories.sql`: ترحيل مستقل لإصلاح قيد أقسام المنتجات في قاعدة موجودة.
- `supabase-fix-rls.sql`: إعادة تطبيق سياسات RLS الآمنة وإصلاح صلاحية دالة إنشاء الطلب.
- عند تحديث قاعدة موجودة، أعيدي تشغيل `supabase-setup.sql` لتطبيق أقسام غوايش وأطقم، وخيار الدفع الكامل أو العربون، وأسماء أعمدة الطلب القياسية وترحيل البيانات القديمة، وحقل `delivery_fee`، وأعمدة معرض الصور وإعدادات الهيدر وطريقة الشحن وسياسات الرفع لحاوية `products`. تتحقق الدالة `create_order` من إرسال رقم الهاتف والعنوان وخيار الدفع صراحةً، وتحسب مبالغ المنتجات وتحفظها في الأعمدة القياسية والمتوافقة مع النظام القديم.
- `catalog.js`, `logo.png`: الكتالوج الابتدائي وشعار المتجر.
